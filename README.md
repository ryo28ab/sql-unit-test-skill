# SQL単体テスト仕様書設計 skill

取得系ストアドプロシージャ・関数の単体テスト仕様書を設計／レビューするskillです。SQL Serverを初期対象とし、仕様・実装SQL・テーブル定義・案件ルールは実行時に渡します。

## 動作

1. 渡された資料を確認する。
2. 合否・確認範囲・テストデータに影響する不足や矛盾があれば、理由を添えて質問する。
3. 回答を待ち、必要な情報が揃った範囲で設計する。
4. 観点とテストケースを対応付け、具体的なデータと期待結果を作る。
5. 不要な組み合わせを整理し、対象外・保留の理由も残す。

正式な仕様書がなくても、文章で業務仕様を説明できます。実装しかない場合は取得仕様を質問します。明示的に暫定案を依頼した場合だけ、仮定を記してドラフトを作ります。回答待ちを時間切れで自己解決しません。

ひな形や過去の指摘は任意です。提供されていないだけで必須資料のように要求しません。実DBへの投入・テスト実行は行いません。

## 導入

`skills/design-sql-unit-tests/` のディレクトリ一式を、利用するAI環境のskill配置先へコピーしてください。`SKILL.md`と`references/`の相対位置を維持します。具体的な導入先や有効化方法は利用環境に合わせてください。

skill機能を持たない環境では、`SKILL.md`と必要な参照ファイルをAIへ渡して同じ手順を指示できます。YAMLを処理するプログラムは含みません。入力を解釈し、質問・設計するのはAIです。

## 使い方

```text
$design-sql-unit-tests

次の取得処理の単体テスト仕様書を作ってください。
仕様：［文章・添付・参照］
実装SQL：［貼り付け・添付・参照］
テーブル定義・依存定義：［貼り付け・添付・参照］
案件ルール・ひな形・過去の指摘：［あれば指定］
出力形式：［会話内の表／Excel等］
不足や矛盾があれば先に質問し、必要な回答を待ってください。
```

入力テンプレートの利用は任意です。案件情報は毎回の依頼・ローカル資料から渡し、共通skill本体へ書き込みません。ローカル資料には`project-inputs/`、出力には`outputs/`を使用できます。両者はGitの管理対象から除外しています。

## 出力

- テストケース一覧：観点、事前条件、引数、手順、具体的な期待結果。
- テストデータと期待結果表：各ケースを独立再現できる行データ。
- 網羅性対応表：仕様・SQL観点とケースの関係、採用／統合／対象外／保留。
- 確認事項：不明点、不一致、影響するケースと確認内容。

テスト設計の完了とテスト実行の合格を区別します。仕様書から観点を抽出し、実装との相違も確認します。

展開したこのフォルダの内容をリポジトリのルートに配置します。既存リポジトリへ加える場合は必要なディレクトリをコピーしてください。新規の場合の例です。

```bash
git init -b main
git add .
git commit -m "Add SQL unit test design skill"
git remote add origin <YOUR_REPOSITORY_URL>
git push -u origin main
```

このパッケージ自体にGitHubへの接続先や認証情報は含みません。

## 動作の確認

`evals/scenarios.md`の依頼をそれぞれ独立した会話で試してください。質問が必要な場合の待機、資料が十分な場合の設計開始、仕様と実装の不一致確認を点検します。実案件のレビュー指摘を追記して運用してください。
