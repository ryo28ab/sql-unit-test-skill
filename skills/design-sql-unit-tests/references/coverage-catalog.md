# 取得系の観点カタログ

仕様・実装・DDLに対応するものだけ採用せよ。一律の必須ケースと扱うな。

| 分類 | 確認候補 | 適用・設計時の注意 |
|---|---|---|
| 引数 | 通常値、対象なし、別ユーザー、NULL、未指定・既定値 | NULLと省略を区別する。無関係な型境界を追加しない |
| 条件 | 成立／不成立、混在、AND／ORと括弧 | 単純ANDは各条件だけ不成立。ORは他条件が結果を覆い隠さないようにする |
| 結合キー | 全キー一致、一部不一致、別対象との混在 | 複合キーの一部欠落を検出できるように値を配置する |
| INNER JOIN | 対応あり／なし、1対多、余計な行の混入 | 親あり子なし等、制約内で表現できる「対応なし」を用いる |
| 外部結合 | 保存側だけ存在、両側一致、外側条件での除外 | WHEREの条件も確認する。常にNULL行が返ると決めない |
| 件数・多重度 | 0／1／複数、意図しない増殖、同値の複数行 | PK・UNIQUEで禁止される重複を用意しない。キーと出力値の重複を区別する |
| EXISTS等 | 対応0／1／複数、NULL | 複数一致で元行が増えないこと等、演算の意味を確認する |
| NULL | 引数・条件列・結合列・返却列、IS NULL、NULL置換 | NULL許容列だけ対象にし、SQLの評価と業務仕様を照合する |
| 境界 | 閾値の直前／一致／直後、開始・終了 | 型・精度における隣接値を用いる。日時の小数秒を決め打ちしない |
| 状態コード | 対象値、対象外の有効値、未定義値 | 有効値と制約を確認する。値の範囲は仕様・案件ルールで決める |
| 返却列 | 列名・型・必要な順序、取得元、別名、全列の値 | 取得元の取り違えも考慮する。契約のない型の細部を要求しない |
| 加工 | CASEの各分岐、ELSE、計算、丸め、桁、文字列加工 | 実在する加工と仕様上の境界に絞る |
| DISTINCT・UNION等 | 重複あり／なし、除去／保持、部分重複 | 行の全列一致が必要な場合を理解し、重複個数も期待値にする |
| 集計 | グループ0／1／複数、境界、NULL、HAVING | 入力0件時の返却形状は集計式・GROUP BYと仕様から決める |
| 順序 | 昇降順、複数キー、同順位、NULL位置 | ORDER BYなしの行順は不問。同順位の固定順は保証がある場合だけ確認する |
| TOP・ページング | 0／上限未満／一致／超過、ページ境界 | 順序の一意性や同順位の契約を確認する |
| 依存 | ビュー等の隠れた条件、現在時刻、実行ユーザー | 単体の境界と固定・代替方法を明記する。未知の定義を推測しない |
| 返却経路 | 結果セット、複数結果セット、OUTPUT、RETURN、エラー | 対象に実在し仕様で必要な経路だけ確認する |

## ケースを増減する基準

- 仕様上の別挙動、既存ケースで検出できない条件欠落、条件間の相互作用、案件の要求基準がある場合に追加せよ。
- 既存ケースで確認できる観点は対応付けて統合せよ。
- 制約上不可能なケース、無関係な型境界、仕様のない性能・負荷・同時実行は、理由を記して対象外または別試験にせよ。明示された権限・セキュリティ仕様を除外するな。
- 「最大件数」等の未定義な上限を捏造せず、確認事項にせよ。
